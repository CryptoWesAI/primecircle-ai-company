01Resolution

Every “4K & 30s” page is selling a spec that isn’t there

I pulled the schema from a live Seedance 2.5 endpoint. The resolution field is an enum, and it contains exactly two values. Measured 

"resolution": { "enum": ["480p", "720p"], "default": "480p" }

No 1080p. No 4K. And the default is 480p — so everyone who never touched that dropdown has been generating at the lowest setting available.

It gets sharper. I checked an older Seedance 2.0 job on the same account. It returned 3840×2160 — genuine 4K. Measured

Seedance 2.5 outputs at lower resolution than Seedance 2.0, and costs 62.5% more per second to do it.

That isn’t a scandal, it’s a trade: you are buying length and control, not pixels. But you should know you’re making it. Runway’s own docs reportedly tell users to switch back to 2.0 when they need 1080p — which tells you ByteDance knows exactly what this model is for. Reported

Working rule

  • Generate at 720p, always. Change the default the moment you open the tool.
  • Budget a separate upscale pass. For client work it is not optional.

Three things fall out of that table, and each one changes how you work.

Pricing is perfectly linear

A 30-second generation costs the same as six 5-second ones. No volume discount, no long-clip penalty. So choose duration for story reasons only — cost is not an argument in this decision.

Audio is free

720p/5s costs 650 credits whether audio is on or off. If you have been switching audio off to save money, you saved nothing and threw away the model’s best feature. Leave it on. Always.

720p is 2.17× the price of 480p

Worth it — and it makes the working loop obvious: prototype at 480p, finish at 720p.

03Grammar

ByteDance published an actual formula

Six slots, in this order. Reported

Subject → Action / Event → Scene & Environment →
Visual Style → Camera Movement or Cut → Audio

Most people write slot 1 and slot 3, then wonder why the camera does nothing.

The order matters because the model reads it as a priority stack. Put what you care about most earliest — and never contradict an earlier slot with a later one. Contradiction, not length, is what breaks these prompts.

04Audio syntax

Four brackets, four output channels

The model is said to route bracket types to different channels. Reported

BracketRoutes to
( )Music
< >Sound effects
{ }Dialogue
【 】Subtitles / on-screen text

So instead of a mushy sentence about “cinematic ambient audio”, you write:

<heavy swell slapping the steel hull, wind buffeting the mic, distant gulls>
(sparse low cello drone, single sustained note, no melody)
{The sea does not care what you planned today.}

Three channels, separately addressed, no ambiguity about which is which.

Honesty note — I tested this and it did not hold up

Prompts using these brackets are accepted without error. But I ran a probe designed to detect whether ( ) actually routes to a dedicated music channel: I requested identical music in plain prose with no parentheses, holding everything else byte-identical.

If the bracket routed music somewhere prose could not reach, that run should have behaved differently. It behaved identically. The model responded to the intent to have music, not to the syntax.

That is one probe against one bracket, so it does not disprove the system — but it is the only firsthand evidence I have, and it points away from the claim. Treat the four-bracket table as a useful way to organise your prompt, which it genuinely is, rather than as a documented routing mechanism.

05Voice

Name the accent, or the model invents one

Native audio is the reason to use this model. Two rules. Reported

Name the regional variety, not the language

“English” gets you a neutral read. “Authentic Los Angeles English” gets you a performance. There is a widely-repeated case where a character kept receiving an unrequested British accent: "American" fixed it, and "American English" did not. The model is more sensitive to how you name the variety than seems reasonable.

Voice is inferred from your image references

Supply a character reference and say nothing about voice, and the model guesses what that face sounds like. It is frequently wrong and always confident. 

Dialogue language: [language + regional variety].
The [character] says, [delivery direction]: {the actual line}

Keep lines short. Lip-sync in 2.5 is good enough that a short line lands cleanly and a long one exposes it.

06References

Fifty slots is a ceiling, not a target

Seedance 2.5 takes 50 references: 30 images, 10 videos, 10 audio clips. Each file gets a handle — @Image1, @Video1, @Audio1. Reported

Rename the handles to roles

@Image1 tells the model nothing. @lead_character, @urban_night_style, @slow_dolly_motion tell it a job. On API surfaces this is the label field on each reference object — I confirmed it exists in the live schema. Measured

Give every reference exactly one job, in a sentence

@lead_character provides Nia's face, hairstyle and jacket only.
@urban_night_style provides the colour palette and lighting, not the subject.
@slow_dolly_motion provides the camera path and pacing, not the content.
@dramatic_voice provides Nia's speaking voice.

Never let two assets define the same property. Two references both claiming “the style” is the most reliable way to get mush.

Do not fill the budget

  • Past a point, extra references dilute strong features and add noise.
  • Conflicting assets weaken direction rather than strengthening it.
  • Video and audio references work best at 5–10 seconds, even though 30s is allowed.

Multi-keyframe storyboarding

You can hand the model an ordered storyboard:

Use @Image 1 through @Image 5 as keyframes in this order.
@Image 1 — she stands at the door, hand on the frame.
@Image 2 — she is halfway down the corridor, lights failing behind her.

Upload the frames individually — separate images align better than a collaged contact sheet. Keyframes control stage order, not literal frame reproduction: they are waypoints, not a flipbook.

07Depth maps

The best-kept secret in the model

This is the most useful technique I found, and almost nobody outside a handful of creators is using it. Reported

The problem it solves: you want to transfer a motion — a dance, a walk, a specific camera move — onto your own character. So you hand Seedance the source video as a reference. And the choreography drifts.

Feed the model a video of someone dancing and it tries to interpret everything — the person, the clothes, the lighting, the room, and somewhere in there, the movement. Feed it a depth map and there’s nothing left to interpret but the motion. You handed it ten variables when you meant to hand it one

A depth map is motion and geometry with every other variable stripped out. No identity, no wardrobe, no lighting, no colour. It is the purest possible expression of “this reference has exactly one job” — the entire design principle of the reference system.

The workflow

  • Build your storyboard normally, in GPT Image 2 or Nano Banana 2.
  • Convert that storyboard into a depth map using the same image model.
  • Hand Seedance three references, each with exactly one job:
    — the depth map → composition, framing, camera geometry, motion
    — a style reference → tone, palette, lighting
    — a character sheet → identity

Reported result: Seedance “understands AI-generated depth maps surprisingly well, giving you much more control with fewer tokens and less need to describe camera angles and compositions.”

That last clause is the kicker. A depth map replaces paragraphs of camera description. You stop writing “slow orbit from a low angle rising to eye level” and just show it the geometry. Fewer words, less contradiction, less drift.

The character sheet pipeline

Multiple creators converged on this independently. Nobody serious generates a hero shot and hopes it holds across a sequence.

  • Create the character once.
  • Turn it into a reference sheet: multiple angles, close-up portraits, clothing, accessories, textures, colours, proportions — instructing the image model to keep design and visual direction identical to the source.
  • Feed the sheet, not the hero shot, as your identity reference.

A sheet gives the model a structured, readable breakdown and forces it to focus on essential visual information rather than stylistic noise. For a multi-scene sequence this is the difference between a character holding and their face quietly becoming someone else by shot four.

08Method

The mistake almost everyone is making

Almost everyone prompting Seedance 2.5 right now is making the same mistake: trying to oneshot the whole video. Recurring observation from creators shipping with 2.5

Thirty-second takes with fifty locked references push the work upstream, into preparation. Building the reference set, writing the brief, deciding the shot before you generate it. That is pre-production — a healthier place for the work to live than the retry button.

The principle that follows: identity, wardrobe, props, location and camera should each have a clear source, instead of fighting each other inside one paragraph of prose. If all five are competing in your prompt text, you are running a 2026 model on a 2024 workflow.

Write beats, not paragraphs

Divide the video into consecutive stages. Give each stage one main change and a visible end state.

Timing: 0-5s   hook — establish subject and world
        5-16s  development — the thing starts happening
        16-25s escalation or proof
        25-30s resolution — land it

Seedance 2.0 rewarded dense, cut-heavy prompts. 2.5 punishes them. 2.0-tuned prompts reportedly produce glitchy output on 2.5, and the model resists rapid one-second-cut styles. Scenes told to breathe do better. Reported

Write ten actions into a four-second clip and you get chaotic morphing. That is not a model failure. That is an instruction failure.

09Camera

“Cinematic” is not a camera move

Specify three things, always, in this order. Reported

SlotOptions
Shot sizewide, medium, close-up, macro, extreme close-up
Angleeye-level, low angle, high angle, overhead, dutch
Movementlocked-off, dolly-in, push-in, pull-back, pan left, tracking, orbit, crane up, handheld, FPV

Terms reported to work reliably: slow dolly-in, orbit, handheld, crane up, locked-off, smooth dolly forward, slow pan left, low tracking shot, pull-back, slow push-in, rack focus.

The rule underneath: a slow push-in feels cinematic; a locked-off static shot feels like a product demo. The word “cinematic” gets you neither — it is a vibe word the model cannot act on. Every vague style adjective (“stunning”, “beautiful”, “photorealistic”) is dead weight. Replace them with things a camera operator could actually execute: rim lighting, shallow depth of field, slow push-in, low tracking shot.

And give the move a reason. A push-in that lands on a reaction is direction. A push-in because push-ins look nice is drift.

10Modes

Text-to-video is the least interesting thing it does

  • Keyframe — supply a first frame and a last frame, prompt the motion between. This is how you make a shot end exactly where you need it.
  • Extend — continue a clip forwards or backwards. Backward extension is the underused one: generate the moment before a shot you already like. It also bridges two existing clips.
  • Smart Edit — change one element in place, region-level, without regenerating the shot. Point at the object or the face, fix that, leave the rest untouched.
  • Long-video mode (beta) — up to 180 seconds, currently via Dreamina.

Why your settings are greyed out

  • Edit mode locks aspect ratio to the input, and duration to input length ±0.3s.
  • First-frame mode locks aspect ratio to your image, but leaves duration free.
11Moderation

The trap that eats your credits

I hit this one personally, and it is the most expensive gotcha in the model.

I submitted an entirely benign prompt — an Icelandic fisherman on a trawler delivering one line of dialogue. No violence, no public figure, no brand, no IP reference. It generated, and then failed. Measured

Job failure — verbatim

errorDisplayCode: "1003: output_moderation_blocked"

[byte-plus] output content rejected by moderation:
OutputVideoSensitiveContentDetected.PolicyViolation:
The request failed because the output video may be
related to copyright restrictions.

Seedance runs three separate moderation stages: Reported

  • a prompt filter on your text, before generation
  • an upload filter — computer vision over your reference images, hunting copyrighted visual elements
  • an output filter that reviews the finished video

Stage three is the one that hurts. Moderation runs during and after inference, so the GPU time is spent and the credits are charged before the rejection fires. Several platforms do not refund it. You pay full price for nothing.

The culprit is music — and it is provable

I ran a five-arm controlled experiment. Same seed, same duration, same resolution, one variable at a time. Measured

ArmMusicDialogueResult
Originalin ( )yesBLOCKED
C1in ( )yesBLOCKED
C2in ( )noBLOCKED
C3noneyesRENDERED
D1plain proseyesBLOCKED
  • The block is deterministic. C1 was an identical resubmission and failed identically. A prompt that trips this trips it every time — you cannot retry your way past it.
  • Dialogue is innocent. C2 removed the spoken line entirely and still failed.
  • Prompt-requested music is the trigger. C3 kept the dialogue, the face, the seed and the sound effects, and removed only the music clause. It rendered clean.
  • It is not a syntax problem. D1 asked for the same music in plain prose, no parentheses, and failed anyway. The model reads the intent to have music, not the bracket. You cannot rephrase your way out.

The mechanism: the model generates a score, an audio fingerprint matcher compares it against copyrighted material, and a match destroys the finished video after you have paid for it.

Context: in February 2026 Hollywood studios formally accused ByteDance of enabling mass copyright infringement via Seedance 2.0. ByteDance publicly committed to tightening controls. Things that passed early in 2026 are blocked now.

Two rules that follow

Never let the model generate music for work you care about. Write no music of any kind, diegetic sound only and lay music in during the edit, where you control the licence. Cleaner mix, and you stop tripping the matcher.

Smoke-test borderline concepts at 4s/480p (240 credits) before committing to 30s/720p (3,905 credits). A 16× cheaper failure is still a failure, but a survivable one.

Note the prompt ceiling: 30,000 characters. Every guide telling you to keep prompts short is giving you a style opinion, not a technical limit.

And note 24 fps. If you are cutting this into a 30 or 60fps timeline, conform it deliberately instead of letting your editor guess.

Known weaknesses — plan around these

  • Physical plausibility in complex motion. Collisions, cloth, liquids under force — that is where it breaks.
  • Many interacting subjects. Stability degrades as subject count rises. Two people talking is fine; a crowd is a gamble.
  • Fast action morphs. Decoherence in rapid sequences persists.
  • Generation stalls. Normal is 2–3 minutes. I saw 8s/720p jobs exceed 20 minutes, and one pass 30, on the day the API went wide. Measured

The shot this model wins at: one clear subject, doing one clear thing, with a camera move that has a reason.

13Field

When to reach for something else

There is no universal winner, and anyone telling you there is has something to sell. Pick per shot. Reported

ModelWins atReach for it when
Seedance 2.5 Duration, reference control. The only model accepting audio reference input. Character consistency across shots, long takes, ads, anything reference-heavy.
Veo 3.1 Cinematic grade, film-like motion blur, professional lighting, strong native audio. The hero shot, where picture quality is non-negotiable.
Kling 3.0 Raw resolution — 4K/60fps — plus a free tier. Volume social output and prototyping on a budget.
Sora 2 Physics, spatial awareness, eye contact and hand gestures. Nothing new — see below.

Do not start a pipeline on Sora 2

OpenAI deprecated the Videos API and the Sora 2 models on 24 March 2026 and published a shutdown date of 24 September 2026 — 47 days from this revision.

Sora 2 still wins on physics, and it will keep topping comparison posts written by people who never checked the deprecation notice. Do not build anything on a model with a published end-of-life inside two months.

The practical split: Seedance 2.5 when a character has to survive more than one shot, Veo 3.1 for the one frame that has to look expensive, Kling 3.0 for volume.

15Loop

The working loop

  • Prototype at 480p. 60 credits/second. Iterate the prompt here, not at 720p.
  • Lock the seed once a take is nearly right, then change one thing at a time.
  • Promote to 720p only when composition and motion are settled.
  • Upscale as a separate pass. Build it into the budget from day one.
  • Use Extend and Smart Edit instead of regenerating. A take you like is expensive to rediscover.
  • Keep audio on throughout — it is free, and it is the differentiator.
  • Keep music out of the generation. Add it in the edit.
